Privacy notice

Updated 13 November 2026

This notice describes how School Exam Backups handles database exports, Google Drive access and backup credentials. It applies to this private backup utility and its planned unattended job.

Purpose and database information

The utility exports the application's PostgreSQL database for disaster recovery. Archives may contain examination content, school records and account information, including password hashes. Session, login-attempt and password-reset-token rows are omitted. The database export streams directly into age encryption before an archive is uploaded.

Google Drive access

Google authorization uses the drive.file permission through rclone. This allows access to files created by the app or specifically made available to it. The utility uses an app-created private My Drive folder to upload encrypted snapshots and read file and folder metadata, including identifiers, owner email addresses, sharing permissions, sizes and MD5 checksums.

These checks confirm the configured destination has a sole-owner access list and that the uploaded ciphertext matches the local encrypted file. MD5 checks transfer consistency; age checks encrypted content during decryption.

Processing, credentials and service providers

Google Drive stores the encrypted archives and associated metadata. Local operation uses a private rclone configuration containing OAuth client credentials and access or refresh tokens.

If unattended backups are enabled, GitHub Actions will run the export and encryption in a private repository's workflow. Its runner will process the unencrypted export in memory and use separate database and Drive credentials stored as GitHub Actions secrets. Temporary encrypted files and the runner's temporary rclone configuration are removed after the job. Archives are not uploaded as GitHub Actions artifacts.

Only the public encryption recipient is supplied to the runner. The private recovery key is stored separately from GitHub Actions and Google Drive. The owner must retain a protected recovery copy. Google and GitHub process information needed to provide their respective storage and workflow services.

Retention and owner controls

Each successful run creates a separate snapshot. There is currently no automatic archive deletion or fixed retention period. The owner can delete archives using Google Drive; Drive's trash and deletion controls then apply.

The owner can disable the workflow and remove its secrets, delete the local OAuth configuration, or revoke the app's access through Google Account settings. Revocation stops future authorized access; it does not delete existing archives.
